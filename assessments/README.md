# Assessment records

No assessment has been conducted under this tracking system as of 2026-11-02.
The earlier NumPy completion record remains in its session folder; see
[PROGRESS.md](../PROGRESS.md) for its evidence and limitations.

Create one dated file, `YYYY-MM-DD-<milestone>.md`, when an assessment occurs.
Keep the record short: milestone/version, questions actually asked, learner answers
or faithful English translations, feedback, evidence-linked rubric ratings,
remaining gaps, and reassessment plan. Do not generate answers in advance.

Evaluate conceptual understanding, mathematical reasoning, implementation
understanding, comparison of methods, and independent explanation. Use
`Not Yet Demonstrated`, `Developing`, `Competent`, or `Strong` per dimension.
An untested dimension is `Not Yet Demonstrated`, not a failing score.

Record assessment status separately from approval. Store the user's exact sign-off
text and date only after they provide it. If they choose to proceed with a gap,
record both the gap and that decision. Link the result from `PROGRESS.md`.
